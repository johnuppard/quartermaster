# Quartermaster routing table (shipped)

This file ships with Quartermaster and is generic. Your own rows, tiers for your own skills and anything the daily self-review learns go in `ROUTING.local.md` next to it; local wins where the two overlap. Do not edit this file by hand on an installed copy; an update would overwrite it.

## How to read this table

1. Find the task type row (none fits: use "Other").
2. Work that fits one agent's context (the normal case): one agent on the Execute tier, then the Check. No split.
3. Work that cannot fit one context and splits: the Plan column says who writes the pieces; the Execute column the tier per piece; the Ceiling how far a piece may step up on its own; the Check the separate agent that verifies.
4. The skill file (the gate) wins over this table on who plans; this table wins on tiers per task type; `ROUTING.local.md` wins over both.

## Tiers (cost rank, most expensive first)

| Tier | Model | Use for | Never for |
|---|---|---|---|
| Fable | claude-fable-5-1 | Only when the user asks for it by name, for a piece or a task | Anything the user did not ask for; never chosen by the foreman |
| Opus | claude-opus-5-5 | The foreman role, planning a new design, judgment with data, analysis and reports, text a client or the public reads, text in a second language, code that touches live systems, checking and editing before the user sees it, legal, money, brand | Bulk mechanical work, sweeps, lookups |
| Sonnet | claude-sonnet-5-5 | Executing a clear spec: file edits per plan, scripts, data pulls, searches, test runs, verifying Haiku work, first drafts of internal text, routine changes with an existing pattern | Final client-facing text, decisions, anything live without an Opus check |
| Haiku | claude-haiku-5-5 | Listing, grepping, classification, summarising logs, extracting fields from many files, checking mechanical done-criteria (file exists, line count, no forbidden character) | Writing anything a person reads as a deliverable, judgment of any kind |

Prices used by the scorecard are in `prices.json`: Anthropic list prices, dated, except Haiku's cache-read price, which is assumed at 10% of its input price. Edit that file if yours differ.

## Task type → tiers

Ceiling = the highest tier a piece may step up to on its own when its agent returns ESCALATE or its verifier answers no. The row's ceiling is the default; the plan may lower it; only the user may raise it. Check = the separate agent that verifies the deliverable: Sonnet for Haiku work, Opus for Sonnet work, a fresh Opus agent for Opus work; never the agent that did the work. Plan = who writes the pieces for a large, splittable task: the foreman from the row (known pattern) or an Opus planner agent (new design). Fable appears nowhere in this table because the foreman never chooses it.

| Task type | Plan | Execute | Ceiling | Check |
|---|---|---|---|---|
| Text a client or the public reads (email, letter, proposal, post, page copy) | Opus | Opus, or the owning skill | Opus | fresh Opus checker + Opus editor |
| Report or analysis with figures | Opus | Opus writes; Haiku and Sonnet pull data | Opus | fresh Opus, figures against sources |
| Website, portal, CMS or app change (live) | Opus | Sonnet on a test copy first; Opus for the live rollout | Opus | Opus on the payload before, fresh Opus as the end user after |
| Scripts, automation, scheduled jobs | Opus | Sonnet | Opus | Opus reads the output; Sonnet runs it |
| Audit or sweep over many files or records | Opus | Haiku finders; Sonnet verifiers | Finders Sonnet; verifiers Opus | Sonnet recount, loop until nothing new |
| Research | Opus | Sonnet searchers in parallel | Opus | Opus synthesis |
| Translation or second-language text | Opus | Opus for anything a client reads; Sonnet draft for internal text | Opus | Opus, native check |
| Ads: any change to a live campaign or spend | Opus | Owning skill, or Opus | Opus | Opus on the exact change, user's yes before anything live |
| CRM or bulk data change | Opus | Sonnet in dry-run first | Opus | Opus on the dry-run digest, user's yes before the live run |
| Contract, legal or compliance review | Opus | Opus, or the owning skill; never below Opus | Opus | fresh Opus |
| Meeting minutes or transcript work | Opus | Owning skill, or Sonnet draft | Opus | Opus |
| Monitoring, incident or bug investigation | Opus | Sonnet investigates; Opus diagnoses | Opus | Sonnet reproduces the fix |
| Building or changing skills, agents or jobs | Opus | Sonnet | Opus | Opus reads; Sonnet runs it |
| Sending, publishing, scheduling, spending (any) | Opus | The mechanical sender runs on Sonnet; the content comes from Opus | Opus | Opus reads the exact payload, user's yes, then send |
| Image or video generation | Opus | Owning skill, or Sonnet | Opus | User picks |
| Lookups, listings, status | none | Haiku | Sonnet | Sonnet, when the result feeds a live change; otherwise the pieces' own evidence |
| Other (no row fits) | Opus | Opus; Sonnet only for a piece with a clear spec | Opus | fresh Opus |

Rule for any row: a send, publish, spend, delete or live write is never executed by the agent that wrote the content, and never before the user's yes.

## Skills by tier

Each installed skill's `model:` line is the source of truth. `runtime/skill-models.json` is the approved snapshot; the daily self-review restores a line an update dropped and lists new skills in `ROUTING.local.md` with the tier this rule gives them:

- Mechanical or tool-wrapper skill → Sonnet.
- Writes text others read, decides, or touches money or legal → inherits the session (Opus).
- Fable → only when the user sets it by hand.

Plugin and marketplace skills that are not files on this machine are not controlled; treat them as Opus for judgment and client text, and say so in the plan.

## Cost rules

- Measured (benchmark, October 2026, two file-reading tasks, two runs each): splitting across Haiku, Sonnet and Opus cost 1.9 and 2.8 times as much at list price as one Opus agent and took 2.7 and 3.8 times as long, because every piece re-reads the sources and starts with roughly 100,000 tokens of fixed context (an observation from this machine, not a benchmark figure). The gate in the skill file therefore sends every task that fits one context to one agent.
- Policy, not measured: a separate check on every deliverable is kept because a wrong result costs more than a check; the benchmark also showed that a check is not a guarantee.
- The honest baseline is one Opus agent doing the whole task, measured, not estimated from the pieces' tokens. The scorecard prints no saving line; a saving is claimed only from a benchmark run.
